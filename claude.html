Claude often ran out of room before handing in the work.

Claude Opus 5.5 (default settings) finished and handed in a file on 144 of 220 tasks. The biggest gap was turning a lot of work into a delivered file within fixed limits.

In plain English

Every task had the same limits: at most 14 rounds of work, 24 actions such as web searches, and a cap on how much text the model could write. Claude often spent its allowance researching and planning, then ran out before saving the requested file. When Claude did deliver, its files often scored well. The fix we suggest is training examples that teach the model to save a basic version of the file early and then improve it.

This is not just about file types Claude can't handle. Even on the 205 tasks with no known file-type limitation, Claude finished 150 versus GPT's 200.

Follow-up: what happens with more room?

We re-ran the 62 cut-off tasks from scratch with larger limits: up to 32,000 tokens per reply (was 10,000), 150,000 per task (was 50,000), 28 rounds (was 14) and 48 actions (was 24).

Result: 54 finished, and 53 of those included a file. Four were still cut off and four hit server errors. This suggests the limits explain much of the gap. However, several settings changed at once, and the retry files have not been graded, so this does not replace the main results.

Where Claude's work was stronger

Where both judges agreed, Claude did better on 29 tasks and GPT on 17. Examples include a surveillance report that tied photo evidence to each timeline entry, and the warehouse safety procedure in the worked example. On most tasks the judges could not separate the two models, so this is not an overall ranking.

Suggested training data: deliver first, then improve

A training dataset proposal describes new examples that could teach the model to fix this weakness.

  • Tasks: long, multi-step professional assignments involving input files, research and file creation.
  • Worked examples: sessions that save a basic but complete file early, then improve it.
  • Budget awareness: examples that track remaining limits and spend effort on the essential steps first.
  • Automatic checks: the requested file exists, opens and covers the core requirements before the session ends.
"The opportunity is converting more of Claude's work into delivered outcomes. These tasks show where planning and tool use consume the budget before the professional artifact exists."

How to tell it worked: more correct, complete files within the same limits, not just more tasks marked "done".

The two models were not set to the same reasoning effort: Claude used default settings and GPT used "low". Identical limits do not mean equal computing power. Quality results are provisional.
