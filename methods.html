Methods and limits

How the test was run and graded, and what it can and cannot tell you. For definitions, see the glossary.

What ran

TasksAll 220 public GDPval gold tasks: 44 occupations, five tasks each. See the tasks.
OpenAI modelGPT-6 Astra (gpt-6-astra) with a low reasoning setting, through OpenAI's API
Anthropic modelClaude Opus 5.5 (databricks-claude-opus-5-5) with default settings, through Databricks
AttemptsOne fresh try per task per model (440 in total). All GPT tasks ran first, then all Claude tasks.
ToolsBoth models could run Python code, search the web and work with images. They received the same input files and instructions.
Limits14 turns, 24 tool calls, 10,000 tokens per reply and 50,000 tokens written per task

How it was graded

  • Each model acted as a judge and graded both models' files against each task's original checklist, including point deductions for serious errors.
  • Judges were not told which model made a file (blinded), though writing style or file names could still give hints.
  • For each checklist item, the judge answered pass, fail or unverified (could not tell). Our code then added up the points.
  • Unverified items turn each score into a range. If two models' ranges overlap on a task, we call it unresolved rather than guess.
  • The two judges' results are always shown separately, never averaged. Technical failures are not scored as zero.

880 grading jobs = 440 files or attempts × 2 judges. "Valid" means the judge returned a complete, well-formed grade.

How we chose what to inspect closely

The brief suggests a 20–40 task slice. We ran all 220 tasks instead, because a single unattended job made it affordable and a full run avoids hand-picking. That gives a less biased overall picture. We then chose a 30-task slice for close inspection using a rule written down before the results came in:

  1. Agreement onlyA task counts only if both judges clearly favor the same model; otherwise it scores 0.
  2. Size of gapUse the smaller of the two judges' guaranteed score gaps, so neither judge can inflate it.
  3. Rank occupationsAverage that gap over the occupation's five tasks.
  4. Need evidenceAt least 4 of 5 tasks must have files from both models and four valid grades.
  5. Top six, all tasksTake the top six eligible occupations and keep all five tasks each: 30 tasks, no cherry-picking within an occupation.

Only 17 of 44 occupations had enough evidence, mostly because Claude often handed in no file. The six selected occupations are Customer Service Representatives, Private Detectives and Investigators, Real Estate Sales Agents, First-Line Supervisors of Retail Sales Workers, Computer and Information Systems Managers and Sales Managers. Across these 30 tasks both judges agree on a direction for 16: 6 favor GPT, 10 favor Claude.

Can we trust the judges?

1. Calibration before scaling up

Before grading all 880 jobs, both judges graded 6 tasks (24 assessments, 964 checklist decisions). We reviewed a report on those grades, including the 26.3% marked unverified and the tasks where the judges disagreed. We then approved the full run with the judges and instructions unchanged. This approval let automated grading proceed; it did not confirm that the grades are professionally correct.

2. Do the judges favor their own model?

The Claude judge favored Claude 50 to 26 on tasks it could decide, which is unlikely to be chance (p=0.008). The GPT judge favored GPT 38 to 31, which is within chance (p=0.47). That is why the site leads with tasks where both judges agree, and never averages the two.

3. What the judges could not check

The judges read extracted text and page images; they could not open slides natively, play audio or video, or recalculate spreadsheets. The unverified rate shows this clearly. Both judges also found Claude's work harder to verify, mostly because of missing files: the GPT judge left 17% of GPT's items unverified versus 34% of Claude's, and the Claude judge 13% versus 33%.

Development pilot (kept separate)

Before the full run, a 6-task pilot tested the harness and grading end to end. Its fixes, such as better file inspection and recovery from errors, went into the frozen settings above. Pilot results are not counted anywhere on this site except in the cost table.

Limitations: what this study can't tell you

  • Not an equal-effort match: GPT used a low reasoning setting and Claude used its defaults, so neither was necessarily at its best or at equal cost.
  • One try each: a second run could turn out differently, and we cannot measure how much results vary.
  • Different times: GPT ran before Claude, so web search results may have differed.
  • AI grading: no human experts have checked the grades yet, and judges could not verify 24.3% of checklist items.
  • What judges couldn't inspect: they did not render Office files, recalculate spreadsheets, check citations live, listen to audio or run video/CAD files.
  • Small samples per job: five tasks per occupation are too few to say which jobs a model is good at.
  • Cost: the main runs generated 68.6 million tokens; grading, retries and the pilot add more. The estimated total of about $1,165 (see What it cost) uses list prices, so actual bills may differ.
  • Security: model code ran locally with best-effort restrictions, not in a fully locked-down sandbox.
