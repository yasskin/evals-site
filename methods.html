Methods and limits

What ran

DatasetAll 220 public GDPval gold tasks, 44 occupations, five tasks each
OpenAI modelgpt-6-astra, low reasoning, OpenAI API
Anthropic modeldatabricks-claude-opus-5-5, endpoint defaults, Databricks model serving
AttemptsOne fresh attempt per task per model (440 total); GPT pass first, then Claude
ToolsShared local Python, web and image tools; same reference files and instructions
Limits14 turns, 24 tool calls, 10k tokens per response, 50k generated tokens per conversation

How it was graded

  • Each model separately judged both generators' outputs using the original weighted task rubrics, including penalties.
  • Generator labels were hidden; writing style or filenames may still reveal identity.
  • Judges returned pass, fail or unverified for each criterion; scores were computed in code.
  • Unverified criteria produce score bounds. Paired tasks with overlapping bounds are unresolved.
  • Judges are never averaged; infrastructure failures are not scored as zero.

Limitations

  • Not compute-matched: GPT at low reasoning effort, Claude at endpoint defaults.
  • Single attempts: no measure of run-to-run variability.
  • Sequential passes: GPT ran before Claude, a timing confound for live web research.
  • Grading: automated and uncalibrated against professional review; 24.3% of criterion decisions unverified.
  • Inspection gaps: no full Office rendering or recalculation, live citation checks, audio listening or video/CAD execution.
  • Sample size: five tasks per occupation do not support occupation-level claims.
  • Cost: primary generation used 68.6M metered tokens; grading, retries and pilots are additional. Dollar cost is unreconciled.
  • Security: local execution used best-effort restrictions, not a hardened sandbox.
