Data and code: how to check our work

Every number on this site comes from saved run records. This page lists what was frozen before running, the checks that passed, the code that produced the results and the status of all 440 attempts.

In plain English

A trustworthy evaluation is one someone else can re-check. We fixed the settings before running, recorded a fingerprint (a hash) of every input, saved every request and reply, and never dropped a failed task from the totals.

The pipeline

  1. 1. PreflightChecked all 220 tasks, 10,453 checklist items and 261 input files (1.66 GB) before any paid run.
  2. 2. GenerateOne resumable job ran all 220 tasks with GPT, then all 220 with Claude.
  3. 3. InspectExtracted text and page images from every saved file for the judges.
  4. 4. CalibrateGraded 6 tasks (24 assessments), reviewed them by hand, then approved full grading.
  5. 5. Grade880 blinded assessments, checkpointed one by one.
  6. 6. AnalyzeOffline scripts built every table and chart; no new model calls.

The code

The code is included with the submission rather than on this public site, because it embeds local paths and dataset files. Main pieces:

FileWhat it does
full_run.pyResumable generation job: preflight hashes, both providers, limits, checkpoints, status matrix
full_grade.pySeparate grading workspace: inspect files, blinded judges, approval gates, aggregate reports
retry_claude.pyThe separately labeled larger-limit Claude follow-up
analyze_sectors.py, analyze_plan_items.pyOffline statistics: sectors, costs, judge agreement, slice ranking, failure candidates
build_site_*.pyGenerate this site's data-driven pages
test_full_grade.py and run testsOffline tests for coverage, resume, locking, retries and grading validation

Re-running the job resumes from checkpoints and skips finished work: uv run python full_run.py run --experiment <dir>, then full_grade.py inspect | grade | aggregate --workspace <dir>. Every paid stage needed a recorded human approval.

How the coding agent was used

  • Wrote the harness, grader, tests and analysis scripts, and this site, from a written plan.
  • Ran preflight checks, monitored the unattended jobs and diagnosed failures from saved records, such as the expired login that paused grading.
  • Paid stages, budgets and claims needed explicit human approval; the agent never launched paid work on its own.
