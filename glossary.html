Glossary

No background in AI evaluation needed. Underlined terms elsewhere on the site link here.

The study

Evaluation (eval)
A structured test of an AI model. You give it the same set of tasks, grade the results the same way, and compare.
GDPval
A benchmark published by OpenAI that asks AI models to do realistic paid work from real occupations, such as an auditor's spreadsheet, a lawyer's memo or a music producer's audio track. The name refers to jobs that contribute to GDP (economic output).
Gold task / gold set
The 220 tasks OpenAI released publicly. Each comes with the instructions, any input files, a grading checklist and usually an example answer made by a professional. "Gold" means it is a reference set with expert-made materials.
Model / AI model
The AI system being tested. Here: GPT-6 Astra from OpenAI and Claude Opus 5.5 from Anthropic.
Model configuration
A model plus its settings. Results describe these exact settings, not the companies' models in general. Here GPT used a "low" reasoning setting and Claude used its default settings.
Reasoning effort
A setting that controls how much the model "thinks" before answering. More effort usually costs more and can improve quality. The two models were not set to equal effort, so this is not a perfectly level comparison.
Paired comparison
Both models did the same task, so their results can be compared task by task rather than only as overall averages.
Attempt / run
One try by one model at one task. Each model had exactly one attempt per task (440 in total).

What the models received and produced

Prompt
The written instructions for a task, for example "You are an auditor… calculate the sample size and save it as an Excel file."
Reference files
Input files handed to the model with the prompt, like a spreadsheet of data or a contract PDF. 125 of 220 tasks include them.
Artifact / deliverable
The file the model produces as its answer: a Word document, spreadsheet, slide deck, PDF, audio file and so on. Most tasks require a file, not just a chat reply.
Delivery rate
The share of tasks where the model finished and left at least one file. It shows whether the model produced something, not whether it was any good.
Headline: GPT 211/220, Claude 144/220. Counting files left by attempts that were cut off early: GPT 212, Claude 153.
Tool / tool call
Actions the model can take besides writing text, such as searching the web or running Python code to build a spreadsheet. Each use is one tool call.
Harness
The software we wrote that gives each model its task, runs its tool calls, enforces limits and collects its files. Both models used the same harness.
Token
The unit AI models read and write in, roughly three-quarters of an English word. Token counts measure how much text a model generated and drive cost.
Turn
One round of the model responding (and possibly calling tools) before the harness replies with results.
Limits / budget
Caps applied to every attempt so the test is fair and affordable: 14 turns, 24 tool calls, 10,000 tokens per response and 50,000 generated tokens per task.
Incomplete conversation
An attempt that hit one of the limits before the model said it was finished. Sometimes it had already saved a partial file.
Provider / harness error
A technical failure outside the model's control, such as the company's server timing out or our software failing to read a malformed tool request.

How grading works

Rubric
A checklist written by people that defines what a good answer must contain. GDPval tasks have 14 to 137 items each (median 47).
Criterion (plural: criteria)
One checklist item, for example "The workbook contains a sheet named 'Sample Size Calculation'". Each is worth points; a few subtract points for serious mistakes.
Judge (AI judge)
An AI model asked to grade an answer against the rubric. We used both models as judges, so every file was graded twice: once by a GPT judge and once by a Claude judge. A model therefore also grades its own work, which is why we report both judges and highlight where they agree.
Blinded
The judge was not told which model made the file. Writing style could still give hints.
Verdict: pass / fail / unverified
Pass: the file meets the criterion. Fail: it does not. Unverified: the judge could not tell, for example whether a document is under five pages, or how an audio file sounds. About 24% of verdicts were unverified.
Score
Points earned divided by points available, as a percentage.
Score range (bounds)
Because some verdicts are unverified, each score is a range rather than one number. The low end assumes every unverified item failed; the high end assumes it passed.
Example: 69.4–72.6% means the true score is somewhere in between, depending on items the judge could not check.
Favored / tie / unresolved
For each task, a judge favors one model if that model's entire score range is above the other's. It is a tie only if both scores are exact (nothing unverified) and identical. It is unresolved if the ranges overlap, or if one of the two grades is missing, meaning we cannot tell which is better. Most tasks were unresolved.
Provisional
Not final. The grading is automated and has not been checked by human experts in each occupation, so treat quality results as early signals.
Sector
The industry a task comes from. GDPval groups its 220 tasks into nine sectors, such as Finance & insurance or Health care & social assistance, with 20–25 tasks each.
Statistically significant / p-value
A p-value estimates how often a gap at least this large would appear by luck alone if the two models were really equal. We call a gap significant when p is below 0.05 (less than a 1-in-20 chance). Checking many groups at once raises the odds of a fluke, so for the nine sectors we use an adjusted p (Holm correction) that is stricter.
Example: Claude missed 15 Finance tasks that GPT delivered, and GPT missed none that Claude delivered. That split is very unlikely by chance (adjusted p ≈ 0.0005), so it is significant.

Terms from the findings

Model trainers / research teams
The people at OpenAI and Anthropic who improve their models, often by creating new training data. The GPT and Claude tabs are written for them.
Training dataset proposal
A suggestion for new examples a company could train on to fix a weakness this evaluation revealed.
Retry study
A separate follow-up where Claude's 62 incomplete tasks were run again with larger limits, to see whether the limits caused the failures. It does not replace the main results.
SOP
Standard operating procedure: a step-by-step workplace instruction document.
ESD
Electrostatic discharge: a static-electricity spark that can destroy electronic parts. The worked example is an SOP for handling such parts safely in a warehouse.
